# Задание №4 — Старая карта

**Сухоручкин Артём Андреевич**

Программа выбирает расчистки ходов, максимизирующие ожидаемую прибыль экспедиции.
Решение — в `main.cpp` на C++20.

## Принятые решения

- Граф неориентированный. Состояния разных ходов независимы и фиксируются один раз для данного мира.
- Поскольку `LOOK` и `MOVE` бесплатны, то при `profit >= 0` перед каждым платным открытием завала полностью исследуем доступную область.
- Цель — ожидание `собранная ценность - day_cost * число CLEAR`. Всегда можно закончить экспедицию; `day_cost >= 0`.

## Входная карта и протокол

Формат входных данных сделаем как на ICPC:

```text
n m
day_cost entrance
profit_1 profit_2 ... profit_n
u_1 v_1 p_1
...
u_m v_m p_m
```

`n` — число комнат, `m` — число ходов, `entrance` — вход, `day_cost` — стоимость одного `CLEAR`.
Далее задаются неотрицательные прибыли комнат и рёбра с вероятностями `0 <= p_i <= 1`.
Параллельные рёбра разрешены, петли запрещены; карта может быть несвязной.

Комнаты нумеруются **от 1 до n**, `path_id` — **номер ребра во входе, от 1 до m**.
Команды и ответы используют номера исходной карты, в том числе после DSU-сжатия.

## Алгоритм

Сначала DSU объединяет вершины, соединённые гарантированно целыми рёбрами `p = 1`.
Каждая компонента становится вершиной с суммой её наград; вход переносится в свою компоненту.
Внутренние рёбра удаляются, параллельные сохраняются. После сжатия все оставшиеся рёбра имеют `p < 1`.
Это корректно: достигнув одной комнаты такой компоненты, можно бесплатно достичь остальных.
Далее все маски относятся к сжатому графу.

После полного бесплатного DFS пусть `A` — маска доступных вершин, `U = V \ A`. Награды из `A` уже собраны.
Все ходы из `A` в `U` наблюдались и обвалились: иначе обход достиг бы их второго конца. Рёбра внутри `U` ещё не осматривались,
поэтому их распределение остаётся исходным.

`dp[A]` — максимальная ожидаемая **дополнительная** прибыль; `profit[A]` в неё не входит.
`policy[A]` хранит выбранную внешнюю вершину либо `-1` для `END`.
Ходы к одной внешней вершине сжатого графа эквивалентны по цене и результату.
После расчистки хода к `v` открывается её случайная компонента `K` в `G[U]`.

```text
fail_cut(X, Y) = произведение (1 - p_e) по рёбрам между X и Y.
```

Для непустой маски выбираем фиксированный корень `r`. Вероятность связности графа:

```text
conn[{v}] = 1
conn[mask] = 1 - Σ conn[sub] * fail_cut(sub, mask \ sub),
                    где r ∈ sub ⊊ mask.
```

Внутренняя связность `K` и отказы рёбер её границы независимы, поэтому:

```text
P(K | U, v) = conn[K] * fail_cut(K, U \ K),  v ∈ K ⊆ U.

Q(A, v) = -day_cost + Σ P(K | U, v) * (profit[K] + dp[A ∪ K]).
                     K ⊆ U, v ∈ K

dp[A] = max(0, max Q(A, v) по граничным вершинам v).
```

Маски `A` рассматриваются по убыванию: строгое надмножество имеет большее значение,
поэтому нужные `dp[A ∪ K]` уже готовы. Состояния без входа не нужны.
Вклад `K` прибавляется действиям из `K ∩ boundary[A]`. Нулевая прибыль соответствует `END`.

- `profit[mask]` и `boundary[mask]` строятся через `prev = mask & (mask - 1)`.
- Произведения вероятностей отказа хранятся через суммы логарифмов внутренних рёбер.
  По разности сумм для `X ∪ Y`, `X`, `Y` восстанавливается вероятность разреза за `O(1)`, что уменьшает риск underflow.
- Если маска несвязна даже по рёбрам с `p > 0`, её `conn` равна нулю. Такие компоненты пропускаются.
- Используется прямой перебор `sub = (sub - 1) & mask`.

Runtime DFS работает по исходному графу и через `comp` собирает маску компонент.
После обхода выбирается наблюдавшийся `BROKEN`-ход в `policy[A]`;
после `CLEAR` обход повторяется от исходного входа.

## Сложность и ограничения

Для subset-DP, где `n` — число компонент после DSU-сжатия:

```
Time:   O(n * 3^n)
Memory: O(2^n)
```

Основные таблицы DP и предподсчётов индексируются маской и занимают `O(2^n)` памяти.
Значение `fail_cut` вычисляется за `O(1)` и отдельно для пар множеств не хранится.
Для исходных `N` комнат и `M` ходов DSU занимает `O((N + M) * α(N))` времени,
хранение карты — `O(N + M)` памяти. Расчисток не больше `n - 1`, все обходы занимают `O(n * (N + M))` времени.
Маски хранятся в `int`, поскольку по времени код будет не выполним фактически раньше, чем случится переполнение типа данных, который можно увеличить и до `long long`.

```text
4 3
4 1
0 10 20 12
1 2 0.4
2 3 0.9
1 4 0.9
```

| Прогон | Состояния рёбер 1 / 2 / 3 | Цена дня | Решение и результат |
| --- | --- | --- | --- |
| 1 | OK / BROKEN / OK | 4 | Собираем 22, расчищаем ход №2, получаем ещё 20. `RESULT 42 1 38` |
| 2 | BROKEN / OK / OK | 4 | Собираем 12, расчищаем ход №1, получаем ещё 30. `RESULT 42 1 38` |
| 3 | BROKEN / BROKEN / BROKEN | 50 | Расчистка не окупается; сразу `END`. `RESULT 0 0 0` |
